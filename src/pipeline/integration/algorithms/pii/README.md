## Considered PII Types

The following PII types were defined for detection:

- email
- phone
- ip

## Detection Strategy

PII detection is based on a hybrid approach that combines structured detection using regular expressions (regex) and contextual validation using the DataFog model.

### Regex-based Detection

Regular expressions are used to identify clearly defined structured patterns.

- Email addresses are detected exclusively using regex because they follow a highly structured and stable format.
- Phone numbers and IPv4 addresses are initially detected using regex-generated candidates.
- Regex is also used as a fallback mechanism for phone numbers and IP addresses when DataFog fails technically due to runtime errors, dependency issues, model loading problems, or similar execution failures.

### DataFog-based Detection

DataFog is employed as a contextual validation mechanism for phone numbers and IP addresses, configured with the following engine:

```python
DATAFOG_ENGINE = "smart"
```

This method enables contextual verification of candidate detections generated by regex.

DataFog failures may occur for reasons not directly related to PII detection itself, such as runtime errors, dependency issues, model loading problems, or memory limitations. In those cases, phone and IP detections could otherwise be lost, while email detections would still work because they are regex-based.

To reduce false negatives caused by these technical failures, the pipeline applies a regex fallback for phone numbers and IP addresses whenever DataFog fails technically.

## Decision Rule

For `phone` and `ip`, the preferred detection rule is confirmation by both regex and DataFog.

A detection is considered valid when:

- both methods identify the same PII type
- the corresponding spans overlap within the text

Formally:

```python
if regex_item["type"] == datafog_item["type"] and spans_overlap(regex_item, datafog_item):
    confirmed.append(regex_item)
```

Under this criterion:

- regex acts as a candidate generator
- DataFog acts as a contextual validator
- only mutually confirmed detections are retained

If DataFog fails technically, regex-based phone and IP candidates are retained as a fallback mechanism.

For `email`, detections generated by regex are accepted directly without contextual validation.

## What Happens When PII Is Detected

When PII is detected, the original record is not removed from the dataset.

Instead of deleting or destructively modifying the original content, the pipeline preserves the original text and adds metadata associated with the detection process.

The generated metadata includes:

- `has_pii`: indicates whether the record contains at least one PII detection
- `pii_prop`: numeric value representing the proportion of detected PII relative to the text length
- `pii_spans`: stores detected spans, including:
  - PII type
  - start position
  - end position
  - detected text

Example:

```json
{
  "text": "Contact me at test@example.com or 0981123456.",
  "has_pii": true,
  "pii_prop": 0.45,
  "pii_spans": [
    {
      "type": "email",
      "start": 14,
      "end": 29,
      "text": "test@example.com"
    },
    {
      "type": "phone",
      "start": 34,
      "end": 43,
      "text": "0981123456"
    }
  ]
}
```

## Label Normalization

Since DataFog may return heterogeneous labels, a normalization process is applied to map them to the predefined PII types.

Mappings include:

- email, mail → email
- phone, telephone → phone
- ip, ip_address, ipv4 → ip

Labels that do not match the defined categories are discarded.

## Additional Validations

To reduce false positives, specific validation rules are applied:

- Email: must conform to a valid full email format
- IP: must be a valid IPv4 address composed of four numeric blocks in the range 0–255
- Phone: must contain between 8 and 15 digits; patterns resembling dates or numeric ranges are excluded

## Generated Report

A global report is generated at:

```text
outputs/report/pii_report.json
```

The report includes:

- total number of processed files
- total number of records
- number of records containing PII
- percentage of records with PII
- detection counts by PII type

Example:

```json
{
  "total_files": 39,
  "total_records": 1308377,
  "records_with_pii": 3079,
  "records_with_pii_percentage": 0.24,
  "pii_counts_by_type": {
    "email": 2323,

    "ip": 2514
  }
}
```
